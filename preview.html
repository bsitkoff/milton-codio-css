Keeping Track

Games need to remember things — the score, whether you're alive, which level you're on. In this lesson you'll learn how to use variables to keep track of state, and how the global keyword lets your functions change those values.

Try It Out

Run track.py by typing python3 track.py in the terminal and pressing Enter.

This game has three states: a start screen, the game itself, and a game over screen. Play through the whole cycle.

Notice

  • How do you start the game? How do you restart it?
  • Where does the score display?
  • What triggers the game over?

Now look at the code. Find the state variable and trace how it gets checked in both update() and draw().

Watch: Game Variables + The global Keyword

A short refresher on what variables actually are and how global lets your functions reach out to change them.

Read the Code

Open track.py. The top of the file declares three variables that the whole game cares about: 

import pgzrun
import random

WIDTH = 800
HEIGHT = 600

# These variables control the whole game
state = "start"
score = 0

player = Actor('happy')
player.pos = (WIDTH // 2, HEIGHT // 2)

alien = Actor('alien')
alien.pos = (100, 100)

def update():
    global state, score
    if state == "playing":
        score += 1

Definition: state

A state is a label that tells the rest of the program what mode the game is in. Our game has three states: "start", "playing", and "over".

Change It

Now that you've explored the game, it's time to make changes! Try some or all of these challenges (you may not have time for all of them, and that's ok) — there are no wrong answers, so experiment and have fun.

Challenge 1 — A Faster Game

  1. Open track.py and find the alien actor.
  2. Right below it, add a new variable: alien_speed = 2.
  3. Inside update(), increase the alien's x position by alien_speed every frame.
  4. Run the game. Then try alien_speed = 6. What changes?

Challenge 2 — Lives

Add a lives variable that starts at 3. When the alien touches the player, subtract 1. When lives hits 0, switch state to "over".

Don't forget to global

If a function is going to change a variable that lives outside it, the first line of that function must be global variable_name. Without it, Python creates a brand-new local variable and silently throws away your change.

What the score looks like

StateScore behaviorWhat the player sees
"start" Score is 0 "Press space to play"
"playing" Score goes up by 1 each frame Score in the top-left corner
"over" Score is frozen "Game over — press R to restart"

Save before you run

Codio saves your work automatically, but it's worth pressing Cmd+S before you run the game so you can see exactly which version is on disk.

Debugging — when the score won't change

  • Is global score the first line of your function?
  • Are you spelling the variable the same way everywhere?
  • Try a print(score) right above the line that should change it.

Going Further

"The whole purpose of a program is to manage state." — every CS teacher, eventually.

Want to push further? Pick one of these and write your own version:

Show a hint for adding a high score

You'll need a second variable, high_score, that doesn't reset when the game restarts. Set it once at the top of the file, then in draw() compare it to the current score and update it if the current score is higher. 

global high_score
if score > high_score:
    high_score = score

Then draw it on screen next to the current score.

Show the full solution for Challenge 1

One way to do it — yours may look different and still be right.

alien = Actor('alien')
alien.pos = (100, 100)
alien_speed = 2

def update():
    global state, score
    if state == "playing":
        alien.x += alien_speed
        score += 1

Teaching note

Most 6th graders will conflate "state" with "score" on the first read. Plan to pause after Challenge 1 and have one student narrate what state is doing while another narrates what score is doing — the contrast helps both ideas stick.
